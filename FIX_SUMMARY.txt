PROBLEMA IDENTIFICADO:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
El bot estaba enviando un producto DIFERENTE al que el usuario preguntaba,
tanto en la presentación del producto como en el flujo de pago.

Ejemplo:
  Cliente: "Quiero guitarra"
  Bot: Muestra piano ❌
  Cliente: "Quiero pagar"
  Bot: Envía link de pago para excel ❌

CAUSA RAÍZ:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. Parser de tarjetas usaba fallback que podía devolver producto incorrecto
2. Motor de decisión cambiaba de producto sin validación estricta
3. Búsqueda de productos no diferenciaba bien entre similares
4. Flujo de pago no validaba que el producto fuera el correcto

SOLUCIONES IMPLEMENTADAS:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

✅ 1. PARSER DE PARTES (agent.ts)
   - Validación estricta de ID de producto
   - Solo usa productToShow de decision (no fallback)
   - Rechaza tarjeta si no hay producto válido
   
✅ 2. MOTOR DE DECISIÓN (conversation-engine.ts)
   - Cambio de producto SOLO en payment_intent/confirmation
   - Mantiene contexto actual en otros intents
   - Evita confusión de productos
   
✅ 3. BÚSQUEDA DE PRODUCTOS (conversation-engine.ts)
   - Desempate mejorado cuando hay múltiples similares
   - Score adicional basado en coincidencias exactas
   - Selección más precisa
   
✅ 4. VALIDACIÓN DE PAGO (agent.ts)
   - Detecta desincronizaciones entre producto y tarjeta
   - Registra mismatches en logs
   - Usa tarjeta como fuente de verdad
