═══════════════════════════════════════════════════════════════════════
  📊 SISTEMA DE FALLBACK
═══════════════════════════════════════════════════════════════════════

Orden de prioridad (mayor a menor):

  1️⃣ Configuración en BD (Dashboard)    ← Máxima prioridad
  2️⃣ Variables específicas: TENANT_1_FB_APP_ID
  3️⃣ Variables globales: FB_APP_ID
  4️⃣ Valores por defecto

Ejemplo:
  - Tenant 1 no configura Facebook en dashboard
  - Sistema busca TENANT_1_FB_APP_ID en .env
  - Si no existe, usa FB_APP_ID global
  - Si tampoco existe, Facebook queda deshabilitado

Esto permite:
  ✓ Trabajar local con tu .env
  ✓ Producción con variables Easypanel
  ✓ Cada tenant configura en dashboard
  ✓ Sin conflictos entre ambientes

═══════════════════════════════════════════════════════════════════════
  🔐 SEGURIDAD
═══════════════════════════════════════════════════════════════════════

✓ Credenciales encriptadas en BD
  - CREDENTIALS_ENCRYPTION_KEY para encriptar tokens
  - Tokens de Facebook, Access tokens, Secrets, SMTP passwords

✓ Cookies firmadas
  - COOKIE_SECRET previene falsificación de tenant_id
  - Sin esto, cualquiera podría autenticarse como cualquier tenant

✓ Validación de permisos
  - requireAdmin() middleware para rutas sensibles
  - resolveTenant() valida sesión en cada request
  - Aislamiento total entre tenants

IMPORTANTE:
  - COOKIE_SECRET debe ser fijo (no cambiar)
  - CREDENTIALS_ENCRYPTION_KEY debe ser fijo
  - Si cambias, las credenciales quedan indescifrables
  - Genera con: python -c "import secrets; print(secrets.token_hex(32))"
